# Синхронизация контекста ChatGPT и GitHub

Цель — переносимая, проверяемая рабочая память по проектам между аккаунтами ChatGPT. Этот репозиторий является **документацией**, а не автоматической памятью модели.

## Еженедельная проверка

- Извлекай новые существенные решения, исправления, ошибки, незавершённые задачи и изменения статуса из **доступного** контекста предыдущих разговоров, прикреплённых файлов и разрешённых источников.
- Доступная сводка памяти не равна буквальному чтению всех бесед. Не утверждай, что проверен каждый чат, если нет полного перечня и текста чатов. В отчёте называй границы охвата.
- Сверяй найденное с действующими документами и, когда возможно, с исходниками/коммитами соответствующих проектов. Сообщения в чате не являются доказательством того, что код опубликован или работает.
- Записывай новые подтверждённые рабочие правила в `AGENTS.md`, текущие статусы в `CURRENT_STATUS.md` и профильные документы, ошибки и уроки в `ERROR_LOG.md`, изменения документации в `CHANGELOG.md`.
- У каждой записи указывай дату события (если известна), дату актуализации, источник (беседа/файл/репозиторий), подтверждённость и следующий шаг. Если сведения противоречат друг другу, не стирай старое утверждение без пояснения.
- Не дублируй прошлую неделю, не копируй всю переписку, не выдумывай детали. Если изменений нет, не создавай пустой коммит.
- После записи проверь фактическое содержимое файлов в GitHub и укажи ссылку на коммит либо точную причину, по которой запись не удалась.

## Журнал ошибок

- Фиксируй **ошибки ассистента**, а не только технические дефекты проекта: неверные допущения, лишнее согласие вместо независимого анализа, непроверенные заявления о готовности, пропущенные проверки, нарушения ТЗ, неудобные инструкции.
- Формат: симптом и влияние; откуда известно; причина (только если установлена); способ исправления; предотвращающее правило/проверка; статус.
- Замечание пользователя без независимой проверки обозначай «сообщено пользователем». Не сочиняй первопричину или итог исправления.
- Перед похожей работой сначала прочитай относящиеся к ней ошибки, чтобы применить предотвращающее правило. Повторное появление ошибки отмечай явно, не скрывай.

## Конфиденциальность и права

Репозиторий **публичный**. Не записывай пароли, токены, cookies, ключи API, персональные сведения, частные договоры, сообщения третьих лиц, закрытые исходники, коммерческие конфиденциальные данные и непубличные материалы. При сомнении пропускай чувствительные детали и сообщай о пропуске.

Нельзя автоматически считать, что фоновая задача имеет доступ ко всем чатам или право записи в GitHub. При недоступном подключении подготовь отчёт/предлагаемые изменения, не заявляй об обновлении репозитория.

## Новый аккаунт

Подключить GitHub с доступом к репозиторию. В новом чате написать:

> Открой https://github.com/HRAKEH/4gpt. Прочитай README.md, AGENTS.md, SYNC_POLICY.md, ERROR_LOG.md, CURRENT_STATUS.md и документы нужного проекта. Соблюдай актуальные требования с учётом системных ограничений. Отдели подтверждённые сведения от неизвестных и проверь актуальное состояние исходников.

Файлы GitHub не загружаются автоматически в память любого другого аккаунта. Их нужно открыть и прочитать в конкретной рабочей среде.

## Расписание автоматической задачи

- Еженедельно по понедельникам, ориентировочно 09:00, часовой пояс Europe/Amsterdam.
- Первый запланированный запуск: 2026-11-30.
- Задача создана в аккаунте ChatGPT 2026-11-23. Создание расписания не подтверждает доступность разговоров и GitHub при будущем запуске; проверять отчёт о фактическом выполнении.
