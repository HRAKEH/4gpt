# SellerBot — аналитика маркетплейсов

**Цель:** коммерческий Telegram-бот для продавцов Wildberries и Ozon с отчётностью, остатками, уведомлениями, финансовыми блоками и удобным меню.

## Инфраструктура
- Основной код: `HRAKEH/seller_analytics_bot` (историческое имя репозитория).
- Технологии: Python, aiogram, httpx, SQLite, Docker, Bothost.
- БД внутри контейнера: `/app/data/seller_analytics.sqlite3` — это лишь известный путь, не место для публикации БД.
- Ранее обсуждались схема 14→15, позднее схема 22; актуальную схему установить по основному репозиторию и БД.
- Из прошлых разговоров известны ориентиры версий: 1.0.29 (основная), 1.1.8 (Start/Pro/Business); состояние на текущий день проверять по Git.

## Функциональные требования
- Множество магазинов, выбор магазина, архивирование/удаление, деморежим и /start-меню.
- Отчёты WB/Ozon, сравнение за 30 дней, вчера/период, переобновление данных без неконтролируемых дублей.
- Доходы, выплаты, начисления, удержания, себестоимость, реклама, экономика, остатки, поставки и акции.
- Ozon Global: учитывать BYN/RUB, исходную валюту, курс на дату и источник курса.
- Уведомления объединять, избегать дублей и спама.
- WB 429: соблюдать ограничения и использовать backoff; один подходящий Personal read-only токен.
- Тарифные уровни, возможности самообслуживания и самостоятельный продукт для продаж.

## Известные вопросы/дефекты
- В разные даты были расхождения с бухгалтерскими сверками по количеству/сумме: необходимы точные формулы и сверка по отчётам площадок.
- Ozon push отмен: реализация упоминалась, но подтверждения доставки событий в рабочих логах и резервной БД не было.
- При проверках Ozon Push ранее встречались 404 внешних health/ready и SIGTERM. Не считать текущим дефектом без повторной проверки.
- Возвратные данные и комиссии тестировать на реальных обезличенных примерах.
