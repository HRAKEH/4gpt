# Seller Analytics Bot — Telegram-аналитика WB/Ozon

**Основные источники кода:** репозиторий [HRAKEH/seller_analytics_bot](https://github.com/HRAKEH/seller_analytics_bot). Этот документ — контекст проекта, а не замена исходного репозитория.

## Архитектура, известная из обсуждений
- Python, aiogram, httpx, SQLite, Dockerfile, запуск через `python main.py`, хостинг Bothost.
- Использовалась схема БД v14 → v15, путь в контейнере `/app/data/seller_analytics.sqlite3`.
- Категории данных: заказы, остатки, магазины, финансовые начисления/удержания, отчёты и сверка.
- В логах встречались `Start polling`, `SQLite quick_check OK`, `Started schema=15`.
- Для WB выбран **один Personal read-only токен** с нужными категориями, без одновременного Base+Personal. Для Ozon — Client ID/API Key, опционально Performance. Значения ключей в архиве отсутствуют.

## Требования
1. Интерфейс Telegram с меню `/start`, кнопками выбора магазина, периода и источника: **WB / Ozon / Оба**. Никакого обязательного ручного ввода shop ID.
2. Управление магазинами: выбор из списка, архивирование/удаление, демо-режим.
3. Уведомления не дублировать; сводные остатки отправлять одним сообщением; сообщения меню по возможности заменять, а не засорять чат.
4. Backfill и обновление периода за последние 30 дней, в том числе повтор в тот же день. Нужны правила идемпотентной перезаписи.
5. WB `/supplier/orders`: обработка 429 с backoff и повтором по правилам API. Ошибки авторизации/прав разграничивать и диагностировать.
6. Пагинация Ozon FBO/FBS, подавление дублей, раздельный и объединённый отчёт по маркетплейсам.
7. Для Ozon Global — хранить исходную валюту (в т. ч. BYN), курс и дату курса; проверять нормативную основу применения курса ЦБ РФ.
8. Финансы Ozon: выплаты, начисления, комиссии и удержания с проверяемыми формулами.
9. Не подменять отсутствующие данные нулём. Нельзя объявлять прибыль или API-интеграцию проверенными без фактической сверки.

## Сверка финансов
Различать цену реализации, поступления после удержаний маркетплейса и фактическую прибыль. Для каждого отчёта указывать формулу, дату/часовой пояс, способ обработки возвратов, комиссий, эквайринга, логистики и себестоимости. Прежние частные денежные данные из переписок в этот публичный архив **не включены**.

## Упомянутый прогресс — требует перепроверки
В прошлых обсуждениях фигурировала версия **1.0.2 в main**, зелёные CI и 263 теста, а также исправления Ozon-дублей, прогнозов поставок и финансовых расчётов. Это запись исторического состояния, **не подтверждение текущего деплоя**. Упоминалась ветка `audit/formula-consistency`, с которой предполагалось продолжить аудит.

## Коммерциализация
Самостоятельный продукт с FAQ, инструкцией для новичка и продвинутой инструкцией, тарифными/этапными ограничениями и коротким периодом поддержки. Приоритет — надёжный учёт и доказуемые формулы, а не количество кнопок.
